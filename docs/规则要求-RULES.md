# Sun_Tey 工程规则（RULES）

> 优先级：**正确性 > 可验证性 > 合规 > 速度**。
> 与本文件冲突的「顺手做法」一律作废。执行顺序：用户当前指令 → 本文件 → `docs/施工图-BLUEPRINT.md` → 知识库。

## 1. 不可协商红线

1. **许可证隔离**：gopeed（GPL-3.0）、aria2（GPL-2.0+）**只读设计与文档，禁止复制源码/片段/逐行翻译**。需要同样能力就按行为重新实现，并在注释注明「依据公开行为/文档实现」。
2. **闭源软件零提取**：IDM、迅雷禁止提取 `.exe/.dll/.sys`、资源文件、私有协议、数据库格式。只允许参考公开可观察的产品行为。
3. **不碰 DRM**：不实现 Widevine/FairPlay/PlayReady 解密，不实现「绕过付费」。产品文案统一表述为「任何**非 DRM** 视频」。
4. **去水印限定**：仅固定矩形台标修复，仅用于用户自有素材，默认关闭，README 写明法律边界。
5. **隐私**：扩展只向 `127.0.0.1` 发送白名单字段（url/referer/UA/必要 cookie）；禁止上传页面正文、禁止任何遥测。任何新增外发必须写进 README。
6. **不伪装成功**：禁止空实现、假进度、吞异常、把未跑过的测试说成通过。做不到就标 `[U]` 或明确失败。
7. **凭据**：token/密码/cookie 不入库、不入 Git、不打进日志。
8. **不破坏用户数据**：迁移与清理脚本必须先备份且可回滚；禁止批量删除非本任务产物（尤其研究资料目录与其上游克隆）。

## 2. 证据纪律（沿用知识库约定）

`[V]` 已执行验证（命令真跑，输出可复现）｜`[S]` 源码证据（`path:line`）｜`[B]` 二进制/打包证据｜`[I]` 推断未证实｜`[U]` 未验证

- 改结论必须**保留或升级**证据标记，不能无证据改写。
- 文档/UI/提交信息里的「支持 XX」句式必须能被一条命令或一个用例证明。
- 「本机跑过」不等于「用户机器能用」：装机类结论必须来自干净环境，否则 `[U]`。

## 3. 架构约束

1. 任务生命周期的**唯一入口**是 Dispatcher；任何模块不得私开任务状态机。
2. 协议以 Fetcher 形式插拔（http/torrent/magnet/playlist），新增协议不改调度器。
3. UI 壳不做网络与分片 IO；内核不弹模态框；两者只经 §5 REST/IPC。
4. 全局 HTTP 客户端只有一个（含代理、限速、UA、连接池策略）；诊断用途可另建但必须在名字里写明 `diagnostic`。
5. 状态与配置必须落盘可恢复，重启后任务不丢、不重复下载。
6. 禁止为单功能重构全局；禁止跨层直连（UI → 内核内部包）。
7. 公开 API 形状（路径/字段/枚举）一经发布只增不改；破坏性变更需要主版本 + 迁移说明。

## 4. 代码规范

- Go：`gofmt` + `go vet` 必须干净；`golangci-lint` 不新增抑制；错误必须带上下文（`fmt.Errorf("...: %w", err)`）。
- 并发：每个 goroutine 必须有明确退出路径与 `context.Context`；禁止裸 goroutine 泄漏；共享状态用 mutex/channel，禁 data race（CI 跑 `go test -race`）。
- 命名：全仓标识统一 `suntey` / `Sun_Tey`；不残留 `fastdl` 字样（含注册表键、管道名、UA、NSIS 产品名）。
- 注释：解释「为什么」，尤其在算法与合规边界处；关键不变量写进注释。
- 零占位：`TODO` 必须带 issue 编号，且不允许在已发布路径上出现「未实现」分支。
- 依赖最小化：新增第三方依赖必须记录 许可证 + 体积影响 + 维护状态；优先标准库。

## 5. 测试与门禁

提交前本地必过：
```
cd core && go vet ./... && go test -short -race ./... -count=1 && go build ./...
```
合入主干额外：`golangci-lint run`、`go test ./... -count=1`（含 long）、扩展端到端脚本、打包构建。

- **CI 红了不许合**。测试失败必须分析根因后修复，禁止跳过/删除测试让它变绿。
- 修 bug 必须先有复现用例（先红后绿）。当前唯一已知红项（见 `docs/知识库/04-前代实现体检.md`）：`bttx TestFileSelectionSwitch`（M0 必修）。
- 行为类改动（多线程策略、磁力状态、后处理）必须带**可量化**断言（速度对比、状态迁移、ffprobe 结果）。
- 外部站点用例必须同时提供本地等价夹具，避免 CI 因网络抖动假红。

## 6. 开源与许可

- 建议 **GPL-3.0-only**（与所参考的 gopeed 生态一致、保证回馈）。若你希望更宽松（MIT/Apache-2.0），需先确认无 GPL 衍生代码，再由你签字决定。
- 第三方清单：`THIRD-PARTY-NOTICES.md` 在 `make notices` 生成，列出每个依赖的名称/版本/许可证/用途，含 ffmpeg（LGPL/GPL 构建需说明并给获取地址）。
- 提交历史洁净：不提交密钥、真实用户数据、受版权保护的音视频样本（用合成夹具）。
- 贡献者协议：README 写明「不接受 IDM/迅雷/DRM 相关功能请求」及其原因。

## 7. 依赖与二进制管理

- `packaging/binaries.lock.json`：`{name, version, url, sha256, size, license}`；构建脚本**先校验 sha256 再使用**。
- ffmpeg 不进普通提交（走 Git LFS 或发布期下载）；若改 LFS，README 写清 clone 步骤。
- 禁止在代码里写死 `H:\` / `E:\` 等开发机路径；一律相对路径或配置项。
- 版本号：`主.次.修订`，构建号来自 CI；安装包与内核版本一致并可在设置页看到。

## 8. Git 与发布

- 分支：`main` 保护；功能分支 `feat/<范围>`、修复 `fix/<范围>`。
- 一次提交一件事；提交信息格式 `type(scope): 摘要`（`feat|fix|test|docs|perf|build|chore`）。
- **未经用户明确授权，不执行** `commit` / `push` / `merge` / `tag` / `release`。
- 每个里程碑末打 `vX.Y.Z-rcN`，附 `docs/验收报告/Mn.md` 要点。
- 发布产物：安装包 + 校验和（SHA-256）+ 变更说明 + 已知限制。

## 9. 交付报告模板（每里程碑一份，放 `docs/验收报告/`）

```
里程碑：Mn — 名称（对应 R#）
1. 目标与验收标准（引用施工图原文）
2. 实际改动：文件清单 + 关键函数
3. 执行的命令与真实输出摘要（贴关键行）
4. 结果判据逐条：通过 / 未通过 / 未验证
5. 新增依赖与许可证
6. 已知问题与下一步
7. 证据标记汇总：[V]x 条 [S]x 条 [U]x 条
```

## 10. 给执行 AI 的操作约定

1. 动手前先读：本文件 → 施工图 → `docs/知识库/04-前代实现体检.md`（现状）→ 目标模块源码。
2. 一次只做一个里程碑；跨里程碑的发现记入 `docs/待办.md`，不顺手改。
3. 修改前先 `git status`，不覆盖未提交改动。
4. 不确定就查知识库（`gopeed.com/zh/llms-full.txt（官方全文）` 是官方全文），**查不到就问我**，不要猜产品语义。
5. 跑不动的检查必须说明为什么跑不动（缺依赖/缺网络/缺 GUI），不许静默跳过。
6. 输出必须能复现：给出命令、路径、判据，别写「应该可以」。
