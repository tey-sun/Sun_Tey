## 2. 判据 (a)(b)：运行中改选 / 暂停后改选

施工图要求「修 P1-1（live 注册表时机），并补两条测试；不允许改到测试变绿」。

| 判据 | 测试 | 结果 |
|---|---|---|
| (a) 运行中连续两次改选均生效 | `bttx.TestFileSelectionSwitch`（a→b→a+b，中途不 sleep） | PASS `[V]` |
| (b) 暂停后改选 → 恢复后选择仍生效 | `bttx.TestFileSelectionPauseResume`（本次新增） | PASS 4.04 s `[V]` |

实现侧（前一轮已落地，本轮补测试）：`Engine.registerTask` 在 torrent 注册的同时发布 `liveSelection`；
`SetFileSelection` 先改 piece 优先级、最后 `live.set(sel)`；`Run` 每个 tick 重读 `live.get()`，
所以完成线跟着运行期改选走，暂停期间的改选由 `manager.SetFileSelection` 落到 `task.BTSel`，恢复时 `Run` 用 `ParseSelection(task.BTSel)` 重新登记。

### 新测试为什么不是「摆设」

`TestFileSelectionPauseResume` 用**构造上无竞态**的方式做判据：种子端**扣掉 a.bin 的数据**（写空文件），
于是 a-only 任务「能连上对端、永远下不完」；暂停后把选择改成 b.bin 并持久化 `BTSel="1"`，
恢复后唯一能完成的路径就是** honour 暂停期间的改选**。断言：`SetFileSelection` 在暂停期返回
`ErrBTNotRunning`、恢复后 `Run` 正常返回、`task.Size == 96 KiB`、`b.bin` 与种子字节一致。

变异验证（证明断言真的在守着行为）：把 `Run` 里的
`e.registerTask(task.ID, t, ParseSelection(task.BTSel))` 改成 `e.registerTask(task.ID, t, nil)` 后，

```text
    bttx_test.go:735: resumed task never completed: the paused-window selection was not honoured
--- FAIL: TestFileSelectionPauseResume (113.53s)
FAIL    github.com/tey-sun/suntey/core/internal/download/bttx    115.151s
```

改回原实现后恢复 PASS，`MUTATION-TEST` 标记已从源码移除（`[V]`）。

顺带做的测试重构：抽出 `fileTreeTorrent` / `twoFileTorrent` / `awaitSeedComplete`，
三个选文件用例共用同一份 fixture（原来复制了三遍）。
