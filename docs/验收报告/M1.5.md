## 2. 续传矩阵（`scripts/test_resume_matrix.py --go`，默认 32 MiB / 4 连接 / throttle 0.09）

重下字节 = 服务端两次进程累计**载荷**字节 − 文件大小；完美续传 = 0。
快照每 2 s 落盘（`httpx.PersistEvery`），强杀时未落盘的在途字节属于 R11 第 2 条「最坏丢失 ≤2 s 进度」的既定代价，
本次参数下的窗口预算是 1 456 355 B（占 4.34%），实测重下量远低于它。

## 3. 真进程 kill 续传验证（本轮补测：同一场景 4 个强杀点）

`Core.kill()` 走的是 `taskkill /F /PID`（等价崩溃/断电，不触发任何优雅保存），杀的是真实的
`suntey-core.exe serve` 进程；重启后由内核自己完成「崩溃态修正 → 自动续传 → 校验 → 改名」。
判据只看两件事：**服务端重发了多少字节**、**最终文件 SHA-256 与完整下载是否一致**。

| 强杀时机 | 强杀时已持久化 | 重下字节 | 占比 | SHA-256 | 结论 |
|---|---:|---:|---:|---|---|
| 8% | 2 883 584 B | 131 072 | 0.39% | 一致 | PASS |
| 25%（默认） | 8 519 680 B | 131 072 | 0.39% | 一致 | PASS |
| 50% | 17 039 360 B | 393 216 | 1.17% | 一致 | PASS |
| 92% | 31 129 600 B | 65 536 | 0.20% | 一致 | PASS |

```text
# 复现命令（每轮一套独立 store 与下载目录，互不污染）
python -X utf8 scripts/test_resume_matrix.py --only A --kill-at 0.08
python -X utf8 scripts/test_resume_matrix.py --only A            # 默认 0.25
python -X utf8 scripts/test_resume_matrix.py --only A --kill-at 0.5
python -X utf8 scripts/test_resume_matrix.py --only A --kill-at 0.92
# 每轮末行均为：结论：PASS 1 / PASS* 0 / [U] 0 / FAIL 0
```

**为什么多点扫描有意义**：单连接顺序下载的进度是 `task.Downloaded`，分片下载的进度是每块
`Downloaded` 之和，两者的快照路径不同；92% 也是最容易暴露「最后一块边界」和
「改名覆盖已有文件」的位置。四次全部字节级一致，才敢说续传不是「恰好一次运气好」。

## 5. 本轮修掉的 4 个真问题

1. **`Accept-Ranges: none` 被二次探测**：旧逻辑对任何「没说 bytes」的响应都再发一次确认请求，
   对显式 `none` 的服务器等于每次探测白下一条全量响应，还在服务器上留下 2 条并发连接
   （矩阵 E 实测峰值从 2 → 1）。现在显式 `none` 直接信任，并在确认前释放探针自己的连接 `[V]`。
2. **`freePath()` 跨盘改名**：旧实现只在文件名上加序号却丢了目录，跨盘时 Windows 直接报
   「cannot move the file to a different disk drive」，把已经下完的任务判成错误；同盘更糟——改名真的成功，
   文件却落进进程工作目录，用户在下载目录里找不到刚下完的东西。现在序号加在**同一目录**里 `[S]`。
3. **矩阵脚本自己假绿**：E2 原先把「重启后整文件重下」的字节记成探针开销（报 0 B）。
   改为按「开放窗口 vs 小窗口」区分载荷与探针，并按并发峰值分账，E2 如实报 26.56% `[V]`。
4. **源变更措辞不一致**：任务卡片与错误提示一处说「已变更」一处说「变了」；
   统一为「服务器上的源文件已变更 / 已更新」并同步矩阵断言 `[S]`。

## 6. 未覆盖与已知边界（诚实清单）

* **B 整机重启** `[U]`：脚本不重启真机。等价状态机路径（`Running` → `Paused(crash)` → `AutoResume`）由 A 覆盖，
  「用户暂停永不自动开跑」由 `TestMatrixAutoResumeSkipsUserPaused` 覆盖。**待人工**：下载中直接重启系统，开机后应自动接着下。
* **G 磁力 piece 位图** `[U]`：不造真 swarm。取消/重开不重复校验由 `TestBTResumeAfterCancel` 覆盖 `[V]`；
  **待人工**：公开种子下到一半强杀后重启，应只补缺失 piece。
* **等长替换 + 服务器复用同一 ETag**：检不出来（弱身份被骗过）。施工图认这笔账，
  M8 高级设置提供「续传强校验（每次付头部窗口）」开关，默认关。已记入 `docs/待办.md`。
* **无 Range 服务器崩溃后重下**：协议限制，见 §2 的 PASS\* 说明；M8 记「同 host 无 Range」结论并在 UI 说明。
* **`-race`**：本机无 cgo 工具链，只在 CI linux job 兜底（与 M0 相同）。
* **UI 层的续传体验**：`ResumeNote` 已随任务下发，但界面上的展示与「重下 / 换源」按钮在 M5（零配置与 UI 重做）落地。
