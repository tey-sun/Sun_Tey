## 1. 一句话模型：先证伪，再续传

```
磁盘上有 8 MB   不算数   ->  Stat 实测，越过文件末尾的「已完成字节」一律作废
服务器说没变    不够     ->  size / ETag / Last-Modified（免费）-> 必要时头部哈希
布局自洽        必须     ->  分块连续、不重叠、完整覆盖 [0,size)，否则拒绝按它写盘
三条都过        才允许   ->  在旧字节后面继续写；任何一条不过 -> 保留文件 + 人话说明
```

核心判断：**「静默损坏的文件」比「慢一点重下」糟糕一个数量级**。所以续传路径上所有可疑情况
一律倒向「不续、说清楚」，倒向「把磁盘文件留着」。反向的诱惑非常真实：清空进度重下永远
不会报错，测试也会变绿——那正是施工图 M1.5 明令禁止的一条 `[S]`。

## 2. 四个决定性取舍

### 2.1 校验开销分层：贵的证据只在没有便宜证据时才付

| 证据 | 代价 | 什么时候用 |
|---|---|---|
| `Content-Length` / `ETag` / `Last-Modified` | 0（探测响应头本来就有） | 每次续传，默认全用 |
| 本地头部 SHA-256（`LocalHeadHash`） | 读自己的盘，近似 0 | 每次续传都复核「本地文件被人改过没」 |
| 远端头部 SHA-256（`HeadHash`，窗口 256 KiB） | `min(窗口, 已下载)` 的流量 | **仅当服务器既没给 ETag 也没给 Last-Modified** |

为什么这样切：读盘免费、读服务器收费。把窗口校验摊到**每一次**续传上，就是「一动就慢、
越用越像重下」的成因；用户的反应不是「更安全」，而是**直接关掉续传**，最后连数据正确性一起失去。
反过来，服务器两个弱头都没给时，头部窗口是唯一证据，这时必须付——矩阵 E1 实测这笔开销
114 688 B（= 当时已下载量），而 ETag 在场时只有 2 B `[V]`。

**已承认的盲区**：等长替换 + 服务器复用同一个 ETag -> 检不出来。默认**不做**每窗强校验，
M8 高级设置给一个「续传强校验」开关（默认关）。不要偷偷把默认打开来换一句「更安全」。

### 2.2 暂停必须带「原因」，自动续传走白名单

`PauseReason`：`user` / `shutdown` / `crash` / `downgrade` / `invalid`。
`AutoResumeAllowed()` 是**白名单**（只捞 shutdown / crash / downgrade），不是「非用户暂停」：
将来新增任何暂停态都会留在原地等用户，而不是被自动续传误捞——那等于替用户决定重下。
用户点过的暂停**永不**自动开跑，这是 IDM/迅雷的一致体验，也是 `TestMatrixAutoResumeSkipsUserPaused` 的断言 `[V]`。

### 2.3 「已完成字节」是谎话的重灾区，一律以 Stat 为准

实测过的三类谎话：

1. **稀疏预分配**：Windows 上 `O_CREATE` + 写偏移会把文件瞬间撑到全长，字节其实没落盘；
   经过复制 / 云盘同步 / 磁盘压缩后可能退化成 0 字节。-> `ClampChunksToFile` 用实测大小夹紧（`model/resume.go:177`）。
2. **进度计数器领先于落盘**：快照每 2 s 一次（`httpx.PersistEvery`），强杀时最多丢 2 s。-> 这是 R11 第 2 条的
   **既定代价**，不是 bug；预算 = 单连接吞吐 x 2 s（本次参数 1 456 355 B），验收判据看的是「重下字节 远小于 预算」。
3. **中间文件被用户删掉/移走**：计数器说有 8 MB，磁盘上 0 字节。-> 清零 + `ResumeNote` 说明「将从头开始」，
   绝不静默（`TestMatrixPartialMissingZeroesProgress` `[V]`）。

推论（M0 已记，M2 继续遵守）：**BT 的进度永远看 piece 位图，HLS 看已完成分片**，都不看文件大小 `[V]`。

### 2.4 中间文件 + 原子改名；改名序号必须留在同一目录

全程写 `xxx.suntey-partial`，完成后 `finishWorkFile()` 改名；改名失败（杀软正在扫刚写完的文件很常见）
重试 3 次（0 / 400 ms / 1200 ms），仍失败就**保留中间文件并标错**——字节一个不丢，点「开始」立刻重试改名。

坑（本轮抓到并修掉）：`freePath()` 早期只在文件名上加 ` (n)` 却忘了拼目录 ——
跨盘时 Windows 报「cannot move the file to a different disk drive」，把下完的任务判成错误；
同盘时更糟：改名真的成功，文件却落进**进程工作目录**，用户在下载目录里找不到刚下完的东西 `[S]`。
任何「生成一个不冲突路径」的函数都必须 `filepath.Join(dir, ...)`。

## 3. 崩溃恢复状态机（四种崩溃，一套收敛）

```
优雅退出（窗口关闭 / POST /shutdown / SIGINT / SIGTERM）
     -> GracefulShutdown() -> stopWith(PauseShutdown) -> 落盘 -> 下次启动 AutoResume 捞回   [V]
taskkill /F（约等于 断电 / 蓝屏 / 进程被杀）
     -> 什么都没写 -> 下次启动把 Running 修正为 Paused(PauseCrash) -> AutoResume 捞回        [V] 矩阵 A 四点
服务器不守 Range 被自动降级
     -> Paused(PauseDowngrade) -> 立即重启跑单连接                                          [V] 矩阵 E
校验判定不可续 / 改名失败
     -> StatusError + PauseReason=invalid -> **永不自动续传**，等人处理                      [V] 矩阵 D
用户点暂停 -> Paused(PauseUser) -> 永不自动续传                                              [V]
```

要点：**「谁让任务停的」必须在停的那一刻写进快照**。进程被强杀时来不及写，所以启动期要把
遗留的 `Running` 改写成 `Paused(crash)`——否则自动续传无法区分「这个任务还在跑」和「上一个进程死在这儿」。

## 4. 实测数字（记住量级，别再重新发明）

| 项目 | 数字 | 说明 |
|---|---|---|
| 强杀后重下（32 MiB / 4 连接 / 8~92% 四点） | 0.20%-1.17% | 上限由 2 s 快照窗口决定，不是随机 `[V]` |
| 断网 32 s | 重下 0 B；retry 25 次；状态仍「下载中」 | 空闲阈值 30 s，重试是**不断任务**的默认行为 `[V]` |
| HLS 48 分片，杀在 18 个 | 重发 98 304 B（1 个在途分片），重复请求已完成分片 0 个 | 分片是天然的续传单位 `[V]` |
| 无 Range 服务器 | 单连接（载荷峰值 1）；崩溃后重下 26.6% | 协议限制，只能整文件重下 `[V]` |
| 身份校验开销 | ETag 在场 2 B；两个弱头都缺 114 688 B | 见 2.1 `[V]` |

## 5. 踩坑清单（本节是本文最贵的部分）

1. **`Accept-Ranges: none` 是权威答复**（RFC 7233 2.3）。旧探测逻辑对任何没说 bytes 的响应
   都再发确认请求，对显式 none 的服务器等于每次白下一条全量响应，还在服务器上留下 2 条并发连接；
   矩阵 E 的「载荷峰值 1」就是靠这个指标判定单连接回退的 `[V]`。确认前还要先释放探针自己的连接（drainClose）。
2. **「没说 bytes」不等于「不支持」**：很多 CDN 支持 Range 但不广告，所以确认探测本身是对的——
   只对显式 none 关掉，别一刀切，否则多线程收益直接消失 `[S]`。
3. **测试脚本自己会假绿**：E2 一度报「重启后重发 0 B」。原因是把「开放窗口的续传请求」
   当成探针记账。**载荷/探针按响应窗口大小分账，不按请求头猜**；探针另算，绝不与载荷混帐 `[V]`。
4. **`HeadHash` 必须返回实际参与哈希的字节数**：服务器可能给得比请求窗口短，两边 n 不同就永远不相等，
   表现为「每次续传都说源文件变了」。本地侧同样按真实长度算（`LocalHeadHash`）`[S]`。
5. **探测失败 不等于 源变更**：网络抖动、临时 5xx、拿不到头部 -> 继续续传（真正的字节防线还在 Range 请求
   与完成校验里）。把抖动变成续传失败，用户只会当成「软件坏了」`[I]`（由矩阵 C 的重试行为佐证）。
6. **迁移期绝不静默重下**：旧库任务要么原样保留进度并打版本号，要么保留磁盘文件 + `ResumeNote`
   + 不再自动开跑；坏行**备份原始键值到副本文件**，而不是吞掉整个任务库；迁移本身失败就拒绝启动 `[V]`。
7. **2 s 窗口不可能变成 0**：想「一点不重下」只能改成每块写盘即 fsync，实测会把吞吐打花。
   把预算写进脚本头部（`window_budget()`），判据才有意义 `[I]`。

## 6. 对后续里程碑的硬约束

| 里程碑 | 必须继承的约束 |
