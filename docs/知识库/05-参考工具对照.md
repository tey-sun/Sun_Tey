# 参考工具可借鉴点（IDM / aria2 / 迅雷）

只记「可验证的事实 + 能落到 Sun_Tey 的设计」。闭源软件一律只参考行为。

## 1. aria2 1.37.0（本机 <研究目录>/aria2，GPL-2.0+）[B/V]

    完整参数表已存 official/aria2-help.txt。与多线程相关的核心选项：
      -s/--split=N                     总连接数（默认 5）
      -x/--max-connection-per-server=N 单服务器上限（默认 1，需显式调大）
      -k/--min-split-size=SIZE          「2*SIZE 以内不切分」——防止把小文件切碎
      -c/--continue                     续传
      -V/--check-integrity              按分片哈希校验
      --optimize-concurrent-downloads   多任务间动态分配带宽（迅雷/IDM 的同思路）
      --file-allocation=none|prealloc|sparse|falloc
      --lowest-speed-limit / --max-tries / --retry-wait
    借鉴：
      1) 分片粒度用「最小分片大小」而非「固定片数」——前代实现 现在是固定 N 路，
         小文件会浪费连接（httpx/minChunk=64KiB 只是下限保护）。
      2) 「服务器上限」和「总连接数」是两个独立旋钮（多镜像/多 CDN 时才有意义）。
      3) 校验优先于「下完就算成功」。
    注意：aria2 是 GPL-2.0+，且无 UI；禁止把它的 C++ 源码搬进 Sun_Tey。

## 2. Internet Download Manager 6.43.1（<研究目录>/Internet Download Manager）

    可验证事实 [B/S]：
      - 自带 Chrome/Edge 扩展（IDMGCExt.crx / IDMEdgeExt.crx，已解包，见 03 号文档）
      - 本地集成走 native messaging 宿主 IDMMsgHost.exe（IDMMsgHost.json 明文）
      - 驱动级流量捕获：idmtdi32/64.sys（TDI）、idmwfp32/64.sys（WFP 过滤）
        => IDM「什么都能抓到」的一部分能力在内核网络过滤，不是扩展
      - 视频处理：IDMVMPrs64.dll（视频预览/解析）、idmvconv.dll（转换）
      - 行为文档 tips.txt：按扩展名列表接管、修饰键强制/豁免、站点账号、调度器重试
    借鉴（行为层）：
      1) 「默认接管 + 可豁免」而不是「默认不接管 + 手动添加」——这就是 IDM 好用的体感来源
      2) 下载完成后对话框是可选的（用户烦的是打断，不是功能）
      3) 失败任务留在队列里定时重试（调度器语义），而不是直接标红终止
      4) 浏览器能覆盖的场景有限，真正的兜底是系统级监听（Sun_Tey 可用
         Windows 的 WFP/ETW 或简单点：轮询浏览器下载目录 + 剪贴板监听，前代实现 已有剪贴板）
    禁止：提取 .dll/.sys/资源/私有协议；IDM 是商业闭源软件。

## 3. 迅雷（<研究目录>/Thunder，闭源商业）

    只记录公开可观察的产品语义（不逆向其私有协议）：
      - 磁力/种子：先拉元数据并展示文件树，用户可选文件后开始下（迅雷的「选文件下载」）
      - 失败/慢时的可解释性：显示「无资源/资源稀少/正在加速」等状态，而不是空白进度
      - 会员加速是它的商业模式（Sun_Tey 不做，也不假装能「加速」）
    借鉴：
      1) 磁力任务必须有「元数据加载中 / 连接 N peer / 无可用资源」三态提示
         （对应 04-前代实现体检.md P1-4）
      2) BT 选文件要能在下载前勾选（迅雷式清单，前代实现 正在做但坏了）
      3) 资源可用性判定：trackers + DHT + 本地 tracker 列表 + 用户自定义订阅（gopeed 已示范）
    禁止：调用其私有云/加速接口、复制其资源文件或数据库格式。

## 4. 三家对照 -> Sun_Tey 的功能底线

| 能力 | IDM | 迅雷 | gopeed | Sun_Tey 底线 |
|---|---|---|---|---|
| 单文件多线程 + 动态再分配 | ✅ | ✅ | ✅(slow-start+steal) | ✅ 必做（gopeed 算法思路 + 自己实现） |
| 断点续传/重启恢复 | ✅ | ✅ | ✅ | ✅ |
| 浏览器接管 | ✅ | ✅ | ✅ | ✅ |
| 网页视频嗅探+列表 | ✅(播放器探针) | ⚠️ | ❌ | ✅ 差异化重点 |
| 磁力选文件 | ❌ | ✅ | ✅ | ✅ |
| 完成后动作（转码/移动/脚本） | ⚠️ 手动 | ⚠️ | ✅ 脚本/webhook | ✅ 内建管线 |
| 零配置 | ❌（要装集成组件） | ⚠️ | ❌ | ✅ 核心卖点 |
