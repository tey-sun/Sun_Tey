## 一句话摘要（防止反复翻文档）

1. **gopeed 多线程的真正算法**：连接数不是一上来开满，而是「先证明服务器能吃下更多再翻倍」——批大小平方增长（`1→2→4→16→256`），失败也要递减 pending 防卡死，429 时暂停扩张；慢连接只在「受害者还需 >3 s」且「块 ≥512 KB」时才偷。
2. **gopeed 装不上扩展的根因**：扩展靠 git 仓库分发，国内访问 github raw/git 受阻 → Sun_Tey 把扩展随安装包分发 + 自动握手，彻底绕开。
3. **gopeed 官方浏览器扩展不做视频嗅探** → 嗅探是 Sun_Tey 的差异化，也是用户的第一需求。
4. **「任何视频」的技术真相是「任何非 DRM 视频」**：直链/HLS/无加密 fMP4 可做，MSE-blob 有限，DRM 不做，且必须在 UI 上诚实提示。
5. **aria2 的分片哲学**：用「最小分片大小」而不是「固定路数」；「单服务器上限」与「总连接数」是两个独立旋钮。
6. **迅雷的可解释性**：磁力必须给「元数据加载中 / N 个对等点 / 暂无可用资源」三态，而不是空白进度条。
7. **前代实现已验证可复用**：多线程 HTTP、HLS 转 MP4、BT/磁力、断点恢复、NSIS 打包都跑通过；缺「统一完成后处理管线」「动态多线程」「去水印」；有一个失败测试待修（M0）。
8. **多线程只在"单连接被限速"时有收益**（M1 实测）：受控限速服务器下 16 路 = 12.27x；
不限速的高 RTT 公网线路上多线程反而 0.67x（分片往返开销）。所以分片必须与 RTT/实测速率联动，而不是一路加到 16。
